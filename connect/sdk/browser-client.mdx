---
title: "Browser client"
description: "Connect end-user accounts from your frontend using a short-lived token."
---

The browser client lets your frontend trigger the Pipedream Connect account-linking flow. It uses a short-lived token generated by your server — your OAuth credentials never touch the browser.

<Warning>
  Never use `@pipedream/sdk/server` or your OAuth credentials in browser code. Use the browser client with a token from your backend.
</Warning>

## Install

```bash
npm install @pipedream/sdk
```

## Create the client

The browser client is initialized with a `tokenCallback` — a function that fetches a fresh connect token from your server whenever one is needed.

```typescript
import { createFrontendClient } from "@pipedream/sdk/browser";

const client = createFrontendClient({
  externalUserId: "user_123",
  tokenCallback: async ({ externalUserId }) => {
    // Call your backend to get a connect token
    const res = await fetch("/api/pipedream/token", {
      method: "POST",
      body: JSON.stringify({ externalUserId }),
      headers: { "Content-Type": "application/json" },
    });
    return res.json(); // returns { token, expires_at, connect_link_url }
  },
});
```

### Configuration options

<ParamField path="externalUserId" type="string">
  Your end user's ID. Passed to `tokenCallback` whenever a new token is needed.
</ParamField>

<ParamField path="tokenCallback" type="(opts: { externalUserId: string }) => Promise<ConnectTokenResponse>">
  Called automatically when a token is needed or has expired. Should return the response from `createConnectToken()` on your server.
</ParamField>

<ParamField path="frontendHost" type="string">
  Override the Pipedream frontend host. Defaults to `pipedream.com`.
</ParamField>

<ParamField path="apiHost" type="string">
  Override the API host. Defaults to `api.pipedream.com`.
</ParamField>

## Connect an account

Call `connectAccount()` to open the Pipedream Connect iframe and guide the user through linking an account.

```typescript
await client.connectAccount({
  app: "slack", // app name slug
  onSuccess: (result) => {
    console.log("Connected account ID:", result.id);
  },
  onError: (err) => {
    console.error("Connection failed:", err.message);
  },
  onClose: (status) => {
    if (!status.successful) {
      console.log("User closed the dialog without connecting.");
    }
  },
});
```

### Parameters

<ParamField path="app" type="string" required>
  The app name slug to connect (e.g. `"slack"`, `"github"`, `"google_sheets"`). Find slugs in the **Authentication** section of any app at [pipedream.com/apps](https://pipedream.com/apps).
</ParamField>

<ParamField path="oauthAppId" type="string">
  The OAuth app ID to use if you have configured a custom OAuth client for this app.
</ParamField>

<ParamField path="token" type="string">
  A token to use directly for this request instead of calling `tokenCallback`.
</ParamField>

<ParamField path="onSuccess" type="(result: { id: string }) => void">
  Called when the user successfully connects an account. `result.id` is the connected account ID.
</ParamField>

<ParamField path="onError" type="(err: Error) => void">
  Called if the connection attempt fails.
</ParamField>

<ParamField path="onClose" type="(status: { successful: boolean; completed: boolean }) => void">
  Called when the Connect iframe is closed, whether or not a connection was made.
</ParamField>

## Full example: server + browser

Here is a minimal end-to-end flow. Your server generates the token; your frontend uses it.

<CodeGroup>

```typescript server.ts
import { createBackendClient } from "@pipedream/sdk/server";

const pd = createBackendClient({
  environment: "production",
  projectId: process.env.PIPEDREAM_PROJECT_ID,
  credentials: {
    clientId: process.env.PIPEDREAM_CLIENT_ID,
    clientSecret: process.env.PIPEDREAM_CLIENT_SECRET,
  },
});

// POST /api/pipedream/token
export async function POST(req: Request) {
  const { externalUserId } = await req.json();
  const tokenResponse = await pd.createConnectToken({
    external_user_id: externalUserId,
    allowed_origins: [process.env.APP_ORIGIN],
  });
  return Response.json(tokenResponse);
}
```

```typescript client.ts
import { createFrontendClient } from "@pipedream/sdk/browser";

const client = createFrontendClient({
  externalUserId: currentUser.id,
  tokenCallback: async ({ externalUserId }) => {
    const res = await fetch("/api/pipedream/token", {
      method: "POST",
      body: JSON.stringify({ externalUserId }),
      headers: { "Content-Type": "application/json" },
    });
    return res.json();
  },
});

document.getElementById("connect-slack").addEventListener("click", () => {
  client.connectAccount({
    app: "slack",
    onSuccess: ({ id }) => console.log("Account connected:", id),
  });
});
```

</CodeGroup>

## Security considerations

- Tokens are short-lived and single-use. The browser client automatically refreshes the token after each successful connection.
- Set `allowed_origins` in `createConnectToken()` to restrict which origins can use the token.
- Your OAuth `clientId` and `clientSecret` must never be included in client-side code or shipped to the browser.
