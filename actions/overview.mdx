## What is an action?

An action is a reusable workflow step that performs a specific operation — sending a Slack message, adding a row to Google Sheets, creating a GitHub issue, and so on. Actions handle authentication, API calls, and error handling for you.

You add actions to workflows as steps. Each action runs in sequence after the previous step and can read data from any upstream step.

## How actions differ from sources

| | Sources | Actions |
|---|---|---|
| **Purpose** | Trigger workflows by watching for new data | Execute operations inside a running workflow |
| **Position** | Always the first step (trigger) | Any step after the trigger |
| **Runs** | When an external event occurs | When the workflow reaches that step |

## Finding actions

When building a workflow, click the **+** button to add a step, then search for an app by name. Pipedream shows all available actions for that app.

You can also browse available apps at [pipedream.com/apps](https://pipedream.com/apps).

## Custom actions

When a pre-built action doesn’t exist for your use case, you can build your own. Custom actions use the same `defineComponent()` structure as pre-built actions and can be reused across workflows or published to the Pipedream community.
